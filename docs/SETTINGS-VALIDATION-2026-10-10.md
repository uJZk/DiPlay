# TiPlay 设置整合与实机验证 — 2026-10-10

## 当前实现

首页设置和 CarPlay 手势统一打开上游 CarPlay 设置菜单。新增选项通过对应的“更多设置”子页进入，
避免重复控件。主菜单草稿在往返子页时保留；取消恢复保存值，“保存并重新连接”才应用需要重连的修改。
子页分别保存，并按已有规则提示重连。

本产品入口固定启用手机到浏览器模式、汽车蓝牙音频和分屏，关闭位置上报，日夜模式只跟随浏览器主题。
上游内部模式、持久化 API 和文件保留，以便同步；不要通过全局 getter 常量替代真实持久化。

三位子代理分别审查设置适用性、编排及诊断显示，最终顺序为：

| 分组 | 保留内容 |
| --- | --- |
| 连接 | 连接配置、手动热点名称/密码、读取热点、浏览器地址/配对、权限 |
| 自动连接 | 自动连接、目标 iPhone、启动连接方式、本机开机启动 |
| 显示 | 30–60 FPS，每档 5，默认 60 |
| 车辆 | 驾驶侧、OEM 标签、AirPlay 图标 |
| 高级 | HEVC，使用各语言的实验性后缀 |
| 诊断 | 诊断报告导出 |

FPS 同时进入 iPhone 的 AirPlay 协商和浏览器流元数据，当前会话不会被菜单草稿修改。
HEVC 控制传到浏览器的压缩视频；软件 HEVC 解码和平滑视频只影响 Android 本机，继续隐藏。
隐藏本机尺寸/分辨率/系统栏/画中画/布局、音频映射与处理、位置及 BYD 专用输出、Wi-Fi Direct、
自动加入热点，以及固定配置的开关。USB 连接选择保留，它仍是有效的连接路径。

底部配置摘要只显示浏览器画布尺寸、FPS 和编码。无效的屏幕日志开关在浏览器模式隐藏，
详细的脱敏连接、能力及重试记录仍写入诊断文件并可导出。

OEM 默认名称改为 TiPlay，用户保存的自定义名称保留。连接用语区分本机与车机浏览器。
热点读取只读：尝试系统接口、已有授权的 Shizuku 或本地 ADB，不切换热点、不自动要求授权。
名称和密码始终可以手填；无法读取密码时保留手动值；异步结果不会覆盖用户随后输入的内容。

浏览器通过现有认证状态通道报告 `prefers-color-scheme`，应用接收并更新 CarPlay 明暗主题。
页面新增 `appearance.js`，Service Worker 缓存版本和资源清单同步更新。
线上页面需要与 APK 一起更新，旧页面不会上报主题。

## 验证与安装

所有依赖、构建及 Node 验证在既有 wslc 容器中完成，没有在 Windows host 安装包。
源码复制到容器磁盘构建，避免 OneDrive 挂载的 Gradle 中间文件问题。
使用 Node 22、JDK 25、现有 Android SDK 和缓存；代理入口为 host 的 `http://localhost:7890`。
私有认证资源只留在容器私有目录，APK 和本地日志在被忽略的 `agent_docs/` 下，不进入 Git。
